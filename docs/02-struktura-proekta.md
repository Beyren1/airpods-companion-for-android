# Этап 2: структура проекта и Gradle

Файлы проекта лежат в корне репозитория. Это пока каркас сборки: исходников Kotlin ещё нет, они появятся на этапе «код 1» (парсер advertising + экран заряда). Сборку я не запускал (в моей среде нет Android SDK), первую проверку сделаете в Android Studio.

## 1. Что меняется под ваши устройства

| Функция | AirPods 4 ANC | AirPods Max (1-го поколения) |
|---|---|---|
| Заряд через advertising | L, R, кейс | Одно значение (у Max нет кейса и раздельных чашек) |
| Крышка кейса, всплывающая карточка | Да | Нет крышки; карточку покажем при снятии с «умного чехла»/включении, если это видно в пакетах |
| Ухо / на голове, автопауза | Да | Да (датчик «на голове») |
| Шумоподавление Off / NC / Transparency | Да | Да |
| Adaptive | Да | Нет |
| Conversational Awareness | Да | Нет |
| Жесты головой | Да | Нет (Apple не поддерживает их на Max 1) |
| Жесты нажатия (настраивается) | Долгое нажатие | Кнопка шумоподавления / Digital Crown: настраиваемость проверим по дампам |
| Переименование, микрофон | Да | Переименование да, выбор микрофона нет |

Значит, AirPods 4 ANC берём как основное тестовое устройство, Max как второе.

## 2. Pixel 9 и root

На стоковом Pixel 9 AAP по L2CAP PSM `0x1001` из обычного приложения, скорее всего, не заработает. Для этапов 3–4 понадобится root. Ставить его сейчас не нужно: этапы 1–2 работают без root. Когда дойдём до этапа 3, понадобится:

1. Разблокировать загрузчик (**это стирает все данные телефона**, сделайте резервную копию).
2. Установить Magisk (патч `init_boot.img` из заводского образа той же версии прошивки).
3. Установить LSPosed: через него наш модуль подправит системный Bluetooth (`com.android.bluetooth`), как это делает LibrePods.

Побочные эффекты root: Google Wallet и некоторые банковские приложения могут перестать работать (проверка Play Integrity). Решите, приемлемо ли это. Подробную инструкцию дам на этапе 3.

## 3. Дерево проекта

```
./
├── settings.gradle.kts        список модулей
├── build.gradle.kts           объявление плагинов
├── gradle.properties
├── gradle/libs.versions.toml  все версии библиотек в одном месте
├── app/                       точка входа: Application, MainActivity, PodsService, разрешения
├── ui/                        Compose-экраны, ViewModel, тема, виджет (Glance)
├── data/                      PodsRepository: объединяет advertising и AAP, DataStore-настройки
├── core-bluetooth/            BLE-сканер, приёмник A2DP-событий, L2CAP-транспорт AAP
└── protocol-aap/              чистый Kotlin: парсер advertising, кодек AAP, state machine, тесты
```

Зависимости модулей (стрелка = «зависит от»):

```
app ──► ui ──► data ──► core-bluetooth ──► protocol-aap
 └──────────────┴──────────────────────────────▲
```

Главная идея: весь разбор байтов лежит в `protocol-aap`, который не знает про Android. Его можно тестировать на компьютере, подсовывая реальные hex-дампы с ваших наушников.

## 4. Kotlin для того, кто знает C++

Короткая шпаргалка, по ходу кода буду комментировать незнакомое.

| C++ | Kotlin |
|---|---|
| `const auto x = 5;` | `val x = 5` |
| `auto x = 5;` (изменяемая) | `var x = 5` |
| `std::optional<T>` | `T?`, доступ `x?.foo()`, значение по умолчанию `x ?: 0` |
| `struct` с `operator==` | `data class Battery(val left: Int?, val right: Int?)` |
| `enum class` | `enum class` или `sealed interface` (как `std::variant`) |
| `uint8_t` | `UByte` / `Byte` (в Kotlin `Byte` знаковый: `b.toInt() and 0xFF`) |
| `std::span<const uint8_t>` | `ByteArray` |
| Callback / поток событий | `Flow<T>`; подписка `flow.collect { }` |
| `std::thread` / `std::async` | корутины: `suspend fun`, `launch { }` |
| Внедрение зависимостей руками | Hilt: `@Inject constructor(...)` |

## 5. Как открыть проект

1. Установите Android Studio (последняя стабильная).
2. Склонируйте репозиторий и откройте его через *File → Open* (или *Get from VCS*).
3. Studio предложит скачать SDK 36: соглашайтесь.
4. Если какая-то версия из `libs.versions.toml` не найдётся, Studio подсветит её; нажмите предложенное обновление.
5. Пока будет ошибка про отсутствующие `PodsApp`, `MainActivity`, ресурсы: это ожидаемо, они появятся на следующем шаге.

## 6. Дампы, которые уже можно снять

Раз есть iPhone, это главный источник протокола для этапа 4:

1. На iPhone поставьте профиль «Bluetooth for iOS» с developer.apple.com/bug-reporting/profiles-and-logs (нужен бесплатный Apple ID), перезагрузите.
2. Подключите AirPods 4 к iPhone и по очереди переключите: Off → NC → Transparency → Adaptive, вкл/выкл Conversational Awareness, смените действие долгого нажатия, переименуйте, смените микрофон. Запишите время каждого действия.
3. Снимите sysdiagnose (одновременно зажать обе кнопки громкости и боковую на 1–2 с), подождите ~10 минут.
4. Настройки → Конфиденциальность → Аналитика → Данные аналитики → `sysdiagnose_…` → поделиться файлом.
5. Пришлите архив сюда (или внутри него файл `.pklg` из папки `logs/Bluetooth`); он открывается в Wireshark.

То же для Max. И с Pixel через nRF Connect снимите advertising AirPods 4 в состояниях из файла этапа 1, это нужно для следующего шага.
